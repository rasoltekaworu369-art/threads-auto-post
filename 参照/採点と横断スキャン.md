# 採点と横断スキャンの手順（Routine A の工程8）

> 🔴 **採点は2段階ある。8-b を飛ばすと、2026-10-19 の初回生成と同じ事故が起きる。**

---

## 8-a｜1本ずつの採点

```bash
grep -n -A 40 "瓜二つ判定チェックリスト・X短文版" 参照/文体憲章_Threads版.md
```

**7項目・各 ○=1点 / △=0.5点 / ×=0点・合格ライン5.5点。**
🔴 **ゲート項目（6 クリーン燃料 / 7 牽引力）が×なら、合計点に関係なく不合格。**

### queue への書き方（🔴 点数だけ書くな）

```json
"採点": "6.5/7",
"落ちた項目": ["2:権威の非定型化(△)"],
"ゲート": "6○ 7○"
```

- **満点なら** `"落ちた項目": []`
- 🔴 **何が落ちたか書かないと、Routine C が「どの項目が弱いか」を判定できない。** 点数だけでは改善に使えない
- **ゲートが×の本は、その場で書き直して再採点する**（点数が5.5以上でも公開不可）

### 採点で絶対にやってはいけないこと

憲章に事故の記録が2件ある。**どちらも「採点を通す最短経路」を探したことが原因。**

| 事故 | 内容 |
|---|---|
| 2026-08-10 | 項目2を埋めるために**毎回年数を挿入**した → ボスに「あからさまにAIが書いてます感」と指摘された |
| 2026-08-11 | 「逆張り公式どおりに書けば1・3・4・7が自動で埋まる」と書いてあった → **毎日9本中4本が同一骨格**になり「テンプレート化はダメだ。AIが書いたとバレる」と指摘された |

→ 🔴 **項目2（権威の非定型化）は「埋めにいく項目」ではなく「入っていたら疑う項目」。** 年数の定型句が入っていたら×。

## 8-b｜🔴 9本の横断スキャン（これが本体）

憲章のチェックリストにこう書いてある。

> **複数本をセットで納品するときの必須スキャン（2026-08-10 新設）:**
> 3本以上を同時に出すときは、採点の前に「同じ構文が2本以上に出ていないか」を横断で見る。
> ボスがワンパターンに気づいたのは、3本まとめて読んだからである。
> **1本ずつの採点では絶対に検出できない欠陥がここにある。**

### 見る対象

| # | 対象 |
|---|---|
| 1 | **権威句**（年数・人数・金額の定型） |
| 2 | **締めの形**（最終文の終わり方） |
| 3 | **断定副詞**（ほぼ全員 / いちばん多い / 必ず / 誰でも / 絶対） |
| 4 | **オリジンの固定語セット**（700万円 / 吉野家 / アファメーション など。1断片は1本だけ） |
| 5 | 🔴 **同じ概念を同じ言い回しで説明していないか** ← **ここが一番漏れる** |
| 6 | 🔴 **導線の一文**（「プロフィールの固定記事へ」の言い方）。**最大3本に付けるので、3本とも違う言い方でなければ違反** |

### 判定

**2本で被ったら片方を書き換える。3本以上で被ったら全部書き直す。**

### 🔴 2026-10-19 に実際に起きた事故（これを繰り返すな）

初回生成で、コンセプトの核である等式が**同じ言い回しで4本に出た。**

```
08:00 『強く願う ＝ 天秤に"まだ無い"という重りを乗せる』
10:00 あなたは自分の天秤に"まだ無い"という重りを1つ乗せています
12:00 自分の天秤に"まだ無い"という重りを乗せていました
14:00 あなたは"まだ無い"という重りを、自分の天秤に乗せていたんです
```

**1本ずつの採点では全9本が合格していた。** 横断で見て初めて出た。

→ 📌 **コンセプトは固定、言い回しは毎回変える**（`concept.md`「コンセプトは固定、入れ物は毎回変える」）。
→ 📌 **等式の正式な形を提示するのは9本のうち1本だけ。** 残りは言い換える。
　 言い換えの例：「持っていないということを自分に申告している」／「持っていない自分のほうを確認している」／
　 「強く願うほど、足りていない現実のほうが先に固定される」（すべて無料部分に出典がある言い方）

#### 🔴 言い換え在庫（使ったら消費される。同じものを2日続けて使うな）

| 手がかり | 無料部分の出典 | 使用状況 |
|---|---|---|
| 申告する | 「願うという行為そのものが、『今は持っていません』という申告になっているんですね」 | 10/19 10:00 で使用 |
| 報告を上げる | 同上の言い換え | 10/20 06:00 で使用 |
| 確認する／確かめる | 「頭は『でも今はそうじゃない』という事実を確認し続ける」 | 10/19 に5本で使用（**消費済み。しばらく使うな**） |
| 点検する | — | 10/20 16:00 で使用 |
| はっきりさせる | — | 10/20 12:00 で使用 |
| 数える | — | 10/20 22:00 で使用 |
| なぞる | — | 10/19 18:00 で使用 |
| 🆕 **皿が沈む** | 「その左の皿に、あなたの『お金持ちになりたい』という思いを乗せます」「重ければ、皿は沈みます」 | **10/20 18:00 で使用** |
| 🆕 **願いの"重さ"** | 「願いの"重さ"だけなんですね」 | **10/20 18:00 で使用** |

🔴 **在庫は7〜9個しかない。9本×毎日で回すとすぐ枯れる。**
→ **枯れたら発明するのではなく、`参照/お手本_無料部分_東洋式の引き寄せ.md` を grep して新しい言い方を採取する。**
→ 採取したら、**この表に1行足す**（足さないと次回また同じものを引く）。

### 自分で機械的に確かめる方法

目で見るだけでは漏れる。**9本を1つの文字列にして、12字以上の一致を数える。**

```bash
python3 - <<'EOF'
import json,collections,re,glob
f=sorted(glob.glob("queue/*.json"))[-1]
ps=json.load(open(f,encoding="utf-8"))["posts"]
seen=collections.defaultdict(set)
for p in ps:
    b="".join(p["tree"])
    for i in range(len(b)-12): seen[b[i:i+12]].add(p["slot"])
dups={k:v for k,v in seen.items() if len(v)>1 and not re.fullmatch(r"[\s。、ー]+",k) and "http" not in k}
shown=[]
for k in sorted(dups,key=lambda k:-len(dups[k])):
    if any(k in s for s in shown): continue
    shown.append(k); print(len(dups[k]),"本:",k,sorted(dups[k]))
print("---","被りなし" if not shown else f"{len(shown)}種の被りを直せ")
EOF
```

⚠️ **URLが1件でも検出されたら、それ自体が違反**（2026-10-19以降、投稿にURLは一切書かない）。
　 上のスクリプトは `"http" not in k` でURLを除外しているが、**除外されたから安全ということではない。**
　 別に `grep -n 'http' queue/<日付>.json` を実行し、**0件であることを確かめる。**
⚠️ **「ではありませんでした。」のような一般的な言い回しは対象外**（上の見る対象1〜5のどれにも当たらない）。

### queue への書き方

トップレベルにこう書く。

```json
"横断スキャン": "実施済み。被り2件を修正（10:00と12:00で等式の言い回しが重複 → 12:00を書き換え）"
```

**「実施済み・被りなし」だけ書いて済ませてはいけない。** 何を見て何を直したかを書く。

## 8-c｜🔴 日をまたいだ被りのスキャン（2026-10-19 新設・機械で行う）

### なぜ 8-b では足りないのか

**8-b は「その日の9本の中」しか見ない。**
2026-10-20 の生成は 8-b を正しく実行し、横断スキャンの記録まで詳しく書き、全9本が合格した。
**それでも、コンセプトの等式が前日と一字も違わずに出ていた。**

```
10/19 08:00  『強く願う ＝ 天秤に"まだ無い"という重りを乗せる』。
10/20 18:00  『強く願う ＝ 天秤に"まだ無い"という重りを乗せる』。   ← 完全一致
```

**その日の中では「等式の正式形は1本だけ」の規則を守っている。** だから 8-b では検出できない。
**毎日これが続けば、7日目には誰が見てもテンプレートに見える。**

### 🔴 目で見るな。コマンドを実行しろ

このとき生成側は「前日との被りも確認した」と報告していた。**報告は事実と違っていた。**
→ **だから、この工程は目視を禁止する。必ず次を実行する。**

```bash
python3 scripts/cross_day_scan.py queue/<日付>.json
```

| 結果 | やること |
|---|---|
| `exit 0`（✅ 被りなし） | 完了。queue に記録して次へ |
| `exit 1`（🔴 被りあり） | **該当する本を書き換えて、もう一度実行する。`exit 0` になるまで繰り返す** |

直近3日と比べて12字以上の一致を出す。**重なる断片は1つに結合して出るので、長いものから直せばよい。**

### 一致が出たときの直し方

| 一致したもの | 判定 |
|---|---|
| **等式の正式形**（『強く願う ＝ …』） | 🔴 **必ず書き換える。** 言い換えは 8-b の一覧から選ぶ（すべて無料部分に出典がある） |
| **命名を導入する一文**（『神の天秤』と呼んでいます 等） | 🔴 必ず書き換える |
| **締めの最終文・導線の一文** | 🔴 必ず書き換える |
| **一般的な語尾**（「〜ではありません。」等） | ⚠️ スクリプトが落としきれなかった分は無視してよい。**ただし12字を超える塊なら直す** |

### queue への書き方

```json
"日跨ぎスキャン": "scripts/cross_day_scan.py を実行。初回 exit 1（6件）→ 18:00の等式を『(言い換え)』に、16:00と10:00の構文を書き換え → 再実行 exit 0"
```

🔴 **「実施済み」だけでは足りない。exit 1 が何件で、何を直して exit 0 にしたかを書く。**
