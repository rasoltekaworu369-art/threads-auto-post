> 🔴 **これが Routine A の唯一の手順書。** ルーティンのプロンプトは「この手順書に従え」としか書いていない。
> **手順書と矛盾する判断をするな。手順書に無いことを発明するな。**
> 手順を変えるときは、このファイルを直して push する（ルーティンの設定は触らない）。

> **この設計の要点:** 文体憲章を「全部読む」のをやめて、「必要な条項だけ grep で引く」に変える。
> Routine は普通のシェルが使えるので、881,000字の資産をリポジトリに置いたまま、
> 毎回コンテキストに乗せるのは **約65,000字** で済む。**削るのではなく、引く。**

## ② 選んだ型の分だけ引く（約20,000字）

```bash

grep -n -A 25 "^### S3\." 参照/文体憲章_Threads版.md
grep -n -A 25 "^### S9\." 参照/文体憲章_Threads版.md
grep -n -A 20 "^### S21\."  参照/文体憲章_Threads版.md
```

- 1条項あたり約2,000字 × 9本分 ≒ **18,000字**
- 迷ったら `grep -n "^### S" 参照/文体憲章_Threads版.md` で条項の一覧だけ見る（約1,000字）

## ③ ネタと語彙は無料部分から引く（約2,000字）

# 第2部｜書き方と納品

## 工程1｜9ツリーの型を決める

`参照/型カタログ_Threads版.md` 末尾の「🔴 次に書くとき、選んではいけないもの」を必ず見てから決める。

| 制約 | 内容 |
|---|---|
| 禁止節 | 挙がっている型は**使わない** |
| 構成型 | 🔴 **9本すべて違う構成型。** 同じ骨格の使い回しは**この仕組みの最大の失敗** |
| 型が足りないとき | 🔴 **発明しない。** 憲章のボス実物由来の型（S1 / S19-1 / S19-3 / T5 など）から借り、**借りた理由を禁止節に書く** |
| 締め型 | **質問／言い切り／労い を3本ずつ**に割る。全部を問いで締めるのは不可 |
| オリジン | 1本につき**1〜2断片だけ**。`参照/オリジン在庫_スピ.md` のA/B/Cの表にあるものだけ。Dは口述待ちなので使えない |

## 工程2｜ツリーを書く（🔴 単発投稿は禁止）

2026-10-18 ボス指示：「単発では反応が出なかったから、全件ツリーで投稿したい」

| 要素 | 規則 |
|---|---|
| **親投稿（tree[0]）** | 🔴 **1文のみ。** 本文の続きを親に含めない。**2文書いた時点で失敗**。目安50字以内 |
| 親に入れる要素 | **毎回違う2〜3個**を組み合わせる：緊急性 / アンマッチ / 恐怖 / アンチテーゼ / 即叶う / 激変 / 希少性 / 私しか言っていない事 |
| 要素の重複 | 🔴 **9本すべてで組み合わせを変える。** 同じ組を2本以上で使わない |
| セルフリプ | **3〜5本**。1本あたり140〜250字。前の投稿に返信する形でスクリプトが自動で繋ぐ |
| 導線 | **9ツリー中2つまで。** しかも**ツリーの最後のセルフリプに置く。親には絶対に入れない** |
| 価格 | 🔴 **CTAに価格を書かない。** 金額はリンク先で見てもらう |
| スピの温度 | **「静」の型。** 尻切れフック「、、」/ 二段フック / (笑) / タメ口崩し / 擬音 / ランキング型 / メタ実況 は**使わない**。権威の年数も**使わない**（S22） |
| 出口 | **4,980円『東洋式の引き寄せの法則』で固定。** 7,980円の商品には触れない |
| 有料部分 | 🔴 **重りの正体・降ろし方・診断21問・台本・30日実行表の中身は書かない** |

各ツリーに**枠**を割り当てる：`06:00 / 08:00 / 10:00 / 12:00 / 14:00 / 16:00 / 18:00 / 20:00 / 22:00`
🔴 これは「その時刻の00〜30分の間に投稿される枠」の意味。**分は指定できない**（GitHubの定時実行が25分前後遅れるため、実際の分はばらつく。それが狙い）。

## 工程3｜採点（`参照/採点と横断スキャン.md` に従う）

🔴 **8-b の横断スキャンを絶対に飛ばすな。** 1本ずつの採点では検出できない欠陥がそこにある。

## 工程4｜納品

`queue/<翌日の日付>.json` を作る。日付は JST の翌日（`date -u -d '+9 hours' +%F` の翌日）。

```json
{
  "date": "YYYY-MM-DD",
  "横断スキャン": "何を見て何を直したかを書く",
  "posts": [
    {
      "slot": "06:00",
      "テーマ": "...",
      "構成型": "D裁判型",
      "開幕型": "③数字1つから",
      "締め型": "⑦短い一撃",
      "親の要素": "アンチテーゼ+恐怖",
      "採点": "6.5/7",
      "落ちた項目": ["2:権威の非定型化(△)"],
      "ゲート": "6○ 7○",
      "tree": ["親投稿。1文のみ。", "2本目の本文", "3本目の本文", "4本目の本文"]
    }
  ]
}
```

- `posts` は9件、`slot` の昇順
- 🔴 `tree` は必須。`text`（単発）は使わない

そのあと：

1. `参照/型カタログ_Threads版.md` 末尾の禁止節を、**今夜使った型で置換する**（追記しない）。履歴は `reaction-log.csv` が持つ
2. 変更を **main に直接コミットして push** する。コミットメッセージは「生成: <翌日の日付> 9ツリー」。**ブランチは切らない**

# 🔴 やってはいけないこと

- **Threads に投稿する。** 投稿は GitHub Actions の仕事。あなたはキューを作るだけ
- **9本の型を揃える。** 「全部同じ骨格で量産された9本」はこの仕組みの最大の失敗
- **親投稿を1文より長くする**
- **単発投稿（`text`）を書く。** 全件ツリー（`tree`）
- **横断スキャンを飛ばす**
- **価格・URL を推測で書く。** `concept.md` に書いてあるものだけを使う
- **オリジン在庫に無い体験を書く。** どれだけ自然に見えても創作はバレる
- **型を発明する。** 自作の型は必ず「整ったAI文」になる
