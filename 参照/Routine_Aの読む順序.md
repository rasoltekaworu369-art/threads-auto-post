# 🔴 やってはいけないこと

- **Threads に投稿する。** 投稿は GitHub Actions の仕事。あなたはキューを作るだけ
- **9本の型を揃える。** 「全部同じ骨格で量産された9本」はこの仕組みの最大の失敗
- **親投稿を1文より長くする**
- **単発投稿（`text`）を書く。** 全件ツリー（`tree`）
- **横断スキャンを飛ばす**
- 🔴 **`python3 scripts/cross_day_scan.py queue/<日付>.json` を実行せずに終える。**
  **目で見た「前日とは被っていない」は信用しない**（2026-10-20 の生成がそう報告して、等式が前日と完全一致していた）。
  **`exit 0` になるまで書き換える**
- 🔴 **`python3 scripts/content_scan.py queue/<日付>.json` を実行せずに終える。**（2026-10-21 新設・中身の被り）
  cross_day_scan は文字列しか見ない。**言い方を変えた同じ話は素通りする。** こちらは題材・テーマ・親投稿・オリジンを見る。
  **`exit 0` になるまでテーマか切り口（場面・オリジン・誰に向けるか）を変える。言い方を変えるだけでは直らない**
- **価格・URL を推測で書く。** `concept.md` に書いてあるものだけを使う
- 🔴 **URLを書く。親・途中のセルフリプ・最後のセルフリプ、どこであっても全面禁止**（2026-10-19 ボス指示）。
  理由：ボスが手動運用しているThreadsアカウントで、**noteのリンクを付けた投稿でシャドバン的な挙動が出た**。
  位置の問題か、URLの存在そのものかは切り分けられていないため、**URLを一切使わない側に寄せる**という裁定。
  → 代わりに **「プロフィールの固定記事を見てください」の形**で誘導する（9ツリー中最大3つ・最後のセルフリプ）。
  → 🔴 **書き終わったら必ず `grep -n 'http' queue/<日付>.json` を実行し、1件も出ないことを確かめる。**
  　 1件でも出たら、投稿側の門（`scripts/post_next.sh`）がそのツリーを落とすので、**その枠は丸ごと失われる**
